PROBLEM STATEMENT

The Critical Security Blindspot in AI Coding

1. Accidental Cloud Leaks

  • Engineers inadvertently paste API tokens, database URIs, and AWS secrets into AI prompt channels.
  • Error stack traces contain live customer PII and internal microservice addresses.
  • Cloud models retain prompts, risking regulatory breaches and intellectual property theft.

2. Invasive Surveillance

  • Traditional security relies on screen scrapers, video watchers, or keyloggers.
  • Deeply invasive to engineer privacy and causes heavy battery/CPU drain.
  • Completely lacks semantic understanding of code facts and developer intent.

3. Risky Bug Fixing

  • Debugging regressions requires manual log copy-pasting to cloud assistants.
  • Untested AI code suggestions introduce subtle downstream bugs.
  • Manual patch application risks silently overwriting concurrent code edits.
SOLUTION & ARCHITECTURE

DevGuard Dual-Agent Local-First Architecture

Agent 1: Synchronous Privacy Gate

  • Inspects developer prompts & clipboard before external delivery.
  • High-priority foreground queue powered by local Gemma 4 E4B.
  • High-entropy regex scanning paired with semantic confidential prose analysis.
  • Exact-span type-safe redaction ([CUSTOMER_EMAIL_1], [REDACTED_SECRET_TOKEN_1]).
  • Fail-closed invariant: Holds delivery (REVIEW) if offline rather than leaking data.

Agent 2: Autonomous Sandbox Repair

  • Diagnoses backend test failures inside disposable Docker sandboxes.
  • Zero screen recording: uses structured pytest traces and code diffs only.
  • Gemma 4 explores code with scoped tools & produces minimal unified diffs.
  • Verified against independent, immutable test oracles.
  • Base-hash conflict protection: Rejects patch if working tree changed (HTTP 409).
CORE FEATURE 1

Exact-Span Redaction & Fail-Closed Gate

Precision Semantic Redaction

  • Multi-tier inspection: High-entropy regex + Gemma 4 semantic reasoning.
  • Catches unformatted secrets regex misses: plain passwords, internal cluster hosts, customer PII.
  • Type-Safe Placeholders: Replaces secrets while preserving 100% of debugging facts.
  • File paths, line numbers, and exception syntax stay intact so AI still fixes the bug.

Deterministic Gate Policy

  • ALLOW: Clean text approved for transmission with verifiable receipt.
  • SANITIZE: Exact spans replaced with safe placeholders before release.
  • REVIEW: Triggered on model offline or ambiguities; prevents uninspected leakage.
  • BLOCK: Rejects malicious inputs (directory traversal, command injection).
  • One-Time Tokens: Delivered payloads cannot be re-transmitted or intercepted.

Strict Opt-In & Privacy Invariants

CORE FEATURE 3

Autonomous Docker Sandbox Repair Agent

Reproducible Sandbox Diagnosis

  • Triggered by test failure signals (e.g., cart quantity calculation regression).

  • Gemma 4 uses strictly scoped tools: read_allowed_file, propose_patch, run_tests.

Independent Test Verification

  • Baseline Check: Verifies regression genuinely reproduces in clean container.
  • Independent Oracle: Evaluates candidate patch against protected trusted_tests.
  • No Fabricated Outcomes: Fails closed if test suite fails or error persists.
  • Generates clean unified diff ready for human operator review.
  • Complete transparency: Model actions and verifier outputs clearly logged.
CORE FEATURE 4

Concurrency Safety & Stale Base-Hash Guard

Cryptographic Base-Hash Validation

  • When an incident is captured, SHA-256 hashes of target files are recorded.
  • Repair agent builds patch against that specific snapshot revision.
  • Before patch application, DevGuard re-hashes the live working tree on disk.
  • If developer edited files while the repair ran → Base hashes mismatch!
  • Result: Instant HTTP 409 Conflict (STALE_CONTENT) — zero code overwrites.

Strict Operator Authority

  • AI Proposes, Human Authorizes: No automated silent code modifications.
  • Idempotent Application: Retrying an already applied patch returns cached state.
  • File-Level Locking: Cross-thread file locks prevent race conditions during apply.
  • Clean Reversion: Unapplied or canceled candidates leave original files untouched.
  • Full Git compatibility: Operates cleanly on standard git branches and diffs.
